# 费曼模式可视化提示

## 使用时机

视觉提示按理解需要触发，不按轮次配额触发。出现以下任一情况时优先考虑用图：

- 用户明确要求画图、画表或对比；
- 当前概念依赖曲线形状、方向、数量级、边界、反馈、收敛或结构关系；
- 用户连续解释同一处仍有困难，一张对照图可以直接暴露概念混淆；
- 新出现的机制、边界或反例仅靠文字容易继续含混。

不要为了美观、填充空间或展示能力而自动配图。简单定义、单一事实和已经讲清的内容继续使用纯文字。一次会话可以有多轮无图，也可以在不同理解节点出现多张图，但同一关系不得反复绘制。

## 输出契约

1. 标明“提示图”，说明它只帮助区分当前问题，不是完整答案。
2. 每次最多一张图；优先用一张包含 2–3 个系列的图。只有宿主原生支持小多图时才使用最多三个面板，并只围绕一个关键区别。
3. 使用甲、乙、丙或 A、B、C 等中性标签；除非任务要求识别答案，否则不要在图下直接宣布哪项正确。
4. 为坐标、单位、条件、方向和时间范围添加标签；数学关系必须画出明确的直角坐标系。
5. 图后只提出一个解释性问题，让用户说明图中的区别及其原因。
6. 图的结论必须来自用户输入、可靠数据或明确的示意假设；不得编造实验值。
7. 用户尚未回应上一张图时，不用新图覆盖同一个问题。

推荐格式：

> 提示图：下面三种情况只改变一个条件。先看图，再用你的话告诉我……

## 选择表示方式

| 要说明的关系 | 优先方式 |
|---|---|
| 数值随时间或输入变化 | 折线图 |
| 类别之间的数量差异 | 条形图，并保留有意义的零基线 |
| 两个变量的关系 | 散点图 |
| 系统流程、因果链、反馈回路 | Mermaid 流程图 |
| 两种或三种情况的关键区别 | 2–3 个小面板 |
| 函数、切线、积分区域、向量、圆和几何构造 | 数学构图脚本 |
| 无法绘图或只有少量离散值 | Markdown 表格或简洁文字示意 |

若宿主可以执行本地脚本：数据比较读取 [chart-spec.md](chart-spec.md)，运行 `../scripts/render_chart.py`；数学构造读取 [math-figures.md](math-figures.md)，运行 `../scripts/render_math_figure.py`。检查实际生成的 PNG 后再展示。若只能渲染 Markdown，使用 Mermaid 或带坐标轴的文字示意；若连 Mermaid 也不能稳定显示，则使用表格。不要依赖外部 CDN、在线渲染服务或未声明的软件包。

## 图形质量

- 只用一个视觉容器，不使用 3D、渐变、阴影或装饰性网格。
- 折线图最多 3 条线；超过 3 条时拆分或将次要信息移入正文。
- 条形图从零开始；折线图不强制从零开始，但必须显示实际刻度和单位。
- 数学图必须同时标出横轴、纵轴、原点 `O`、箭头和轴标签，不能只画一条底部时间轴。
- 标签和刻度必须清晰，不能裁切最长标签。
- 颜色不能是唯一编码，同时使用形状、线型或文字。
- 不符合零基线的图不得随意截断坐标轴；若必须截断，明确标注。
- 比较多个量时，先统一单位或在图中写明归一化公式。
- 图中没有真实数据时应写“示意图”，不能伪装成测量结果。

## 示例：极限与收敛

用户正在解释“趋于一个值”和“到达那个值”的区别。可以绘制一张包含三条示意曲线的折线图：

- A：单调靠近某条水平虚线，但从未到达；
- B：在水平虚线两侧来回摆动，摆动幅度逐渐缩小；
- C：在水平虚线两侧来回摆动，且幅度不缩小。

图后只问：

> A、B、C 中，哪些符合“任意给定一个误差范围，最终都能进入并保持在范围内”？请用你自己的话说明判断依据。

不要在图下直接罗列三者的答案。让用户通过解释和纠正完成判断。

## 示例：控制系统的反馈

若用户把误差、控制器输出和被控对象混为一谈，可画一个 Mermaid 回路：

```mermaid
flowchart LR
  R["目标值"] --> E["误差"]
  E --> C["控制器"]
  C --> P["被控对象"]
  P --> Y["实际输出"]
  Y --> E
```

然后只问：

> 如果控制器把误差乘得更大，但实际输出没有变化，你首先会怀疑这条回路中的哪一段？
